# Design: 0.9.1 correctness hotfix

**Date:** 2026-09-26
**Target release:** 0.9.1
**Source:** project review of `origin/development` at `948b5e0`
**Status:** approved in review (formatMessage approach, fix list, workflow)

## Problem

A review of `development` found defects that the test suite does not see. Each
one below was reproduced with a throwaway Jest test against the real component,
not inferred from reading. Four of them are severe:

1. **Hook called outside render.** `formatMessage` calls `useContext`
   (`src/libs/i18n/utils/formatMessage.ts`), but it runs inside event handlers:
   the CVC info button (`CVCInput.tsx`) and every `modal-*` mode of `DateInput`
   when the picker opens. With the real `React.useContext` both throw
   "Invalid hook call". The suite never sees it because `jest.setup.ts` replaces
   `React.useContext` globally.
2. **AmountInput inflates amounts 100×.** The component emits `"1234.50"` but
   parses its mount-time `value` by splitting on `,`. Remounting with the value it
   emitted produces `"123450.00"`. Pre-filled edit forms, back navigation and
   `ToggleInput` with `inputType='amount'` all remount it.
3. **DateInput instances share state.** A module-level `let externalDate` is
   shared by every instance. With two date inputs, confirming A without scrolling
   saves B's date into A.
4. **A visible toast freezes the app.** `NotificationProvider` wraps the whole
   tree in `pointerEvents='box-only'` while any toast is visible, so no press
   anywhere registers — including taps on the toast itself.

Further verified defects:

5. `Notification.hideAll()` returns the function instead of calling it.
6. The `onPress` passed to `Notification.success/warning/danger/info/show` is
   dropped.
7. `DateInput` with `viewType='button'` opens the picker even when `disabled`
   (operator precedence).
8. `Button` ignores its `fontFamily` prop; `isLoading` does not block presses.
9. `Image` turns a local `require()` source into `{cache: 'reload'}`, which
   renders nothing.
10. `EmailInput` ignores `value` changes after mount, so a form reset has no
    effect.
11. `List` throws `RangeError: Invalid array length` when `isLoading` is set with
    a fractional `estimatedItemSize`.
12. `TabWidget` remounts every tab scene on each re-render because it builds a
    `SceneMap` inline, so state inside tabs is lost.
13. When `rott.config` cannot be resolved, all 113 built-in icons and every
    built-in image disappear. The 2026-06-22 design already decided that a
    missing config must keep the defaults; that part was never implemented.
14. `AmountInput` never shows its currency icon: currency types are `TL`, `USD`,
    `EUR`, while the icon keys are `tl`, `usd`, `euro`.
15. Colors supplied through `RottProvider config` do not resolve as variants,
    because `colorFromVariant` reads only the `rott.config` theme.
16. Importing the package adds enumerable members to `Array.prototype` and
    `String.prototype`, so `for...in` over any array or string in the consumer
    app yields `sortByKey`, `isEmpty` and similar keys.
17. `Header` accepts `goBackFunction` but never calls it.
18. `Container` hides the status bar unless `showStatusBar` is passed; the docs
    list the default as `true`.

## Goals

- Fix 1–17 in code and 18 in the docs, each behind a regression test that fails
  before the fix.
- Remove the global `useContext` mock so hook misuse fails tests again.
- Keep the public API stable. The only additions are one opt-in prop and one
  optional callback field.
- Ship as 0.9.1 so every `^0.9.0` consumer receives the crash and money fixes.

## Non-goals

- Moving theme or language state into React context.
- Replacing `react-native-toast-notifications`.
- Changing the bundled fonts or brand assets (decided separately).
- The remaining parts of the 2026-06-22 design (see Related work).

## Design

### i18n: a hook-free `formatMessage`

`formatMessage` keeps its signature and stops calling hooks.

- A new internal module `src/libs/i18n/utils/activeLanguage.ts` holds the active
  language name (`'en-US'` by default) with `getActiveLanguage()` and
  `setActiveLanguage(name)`. It is **not** re-exported from the `utils` barrel,
  so it does not become public API.
- `RottProvider` calls `setActiveLanguage(resolvedLanguage.name)` during render,
  before its children render. This mirrors how the provider already updates the
  module-level `themeConfig`.
- `formatMessage` resolves messages for the active language (falling back to
  `en-US`, as today) and reuses one `IntlShape` per locale, created with a single
  module-level `createIntlCache()`, instead of building a new intl object and a
  new cache on every call.
- Result: `formatMessage` works during render, in event handlers and outside
  React. The call sites in `CVCInput` and `DateInput` need no change.
- `jest.setup.ts` drops the `jest.spyOn(React, 'useContext')` block. Tests that
  call `formatMessage` at module scope keep working because it no longer needs a
  hook.

### Inputs

**AmountInput**

- The emitted format is unchanged: `"<integer>.<two decimals>"`, for example
  `"1234.50"`.
- The mount-time parser accepts both shapes. A value matching
  `^\d+\.\d{1,2}$` is read as the canonical dot-decimal form: the integer part is
  grouped with thousands dots for display and the decimals become the cents
  field. Any other value keeps today's parsing (`"1.234,50"` → `"1.234"` and
  `"50"`).
- Remounting with an emitted value therefore emits the same value.
- The currency icon maps through `{TL: 'tl', USD: 'usd', EUR: 'euro'}`. A `null`
  `currencyType` still renders no icon.

**DateInput**

- `externalDate` becomes a per-instance `useRef<Date>`, initialised from `value`.
  Every read and write moves to the ref. The unmount reset of the module variable
  is no longer needed.
- The `viewType='button'` press handler calls the existing `openPicker`, which
  already returns early when `disabled` and chooses the modal or native picker by
  `mode`.
- Unchanged on purpose: the mount-time `onDateChange` call, the Turkish default
  placeholder, and the modal config captured on first render.

**EmailInput**

- When `value` is defined the input is controlled and displays `value`.
  Otherwise it keeps its internal state, as today. `onChangeText` fires in both
  modes.
- A consumer passing `value` without `onChangeText` now gets a read-only field,
  which is standard React behavior. This goes in the release notes.

### Overlays

**Notification**

- `NotificationProvider` accepts `blockTouchesWhileVisible?: boolean`, default
  `false`. `RottProvider` accepts `blockTouchesWhileNotificationVisible?: boolean`
  and forwards it. The wrapper uses `pointerEvents='box-only'` only when the
  option is on and a toast is visible; otherwise it is always `'box-none'`.
- The visible-toast counter moves from a module-level variable to provider state
  (`useState` with functional updates), so the wrapper's `pointerEvents`
  re-renders when it changes. It is incremented on show and decremented once, in
  the toast's `onClose` callback. The library fires that callback for `hide(id)`,
  `hideAll()` and auto-dismiss alike, so `hide(id)` no longer decrements a second
  time.
- `Notification.hideAll()` calls `hideAll()`.
- `NotificationModel` gains `onPress?: () => void`. `show()` and the
  `success/warning/danger/info` helpers forward it through the toast `data`, and
  `ToasterNotificationProvider` passes it to `NotificationComponent`, which
  already calls `onPress` and then closes on tap.

### Theme and primitives

**Missing `rott.config` (completes the 2026-06-22 design, asset part)**

- `theme.ts` records whether `require('rott.config')` succeeded.
- Not resolved: the asset bases are `defaultThemeConfig.images` and
  `defaultThemeConfig.icons`, merged with consumer-scanned assets.
- Resolved without `images`/`icons`: unchanged, consumer-scanned assets only.
  This is the documented "empty config" behavior.
- Resolved with `images`/`icons`: unchanged.
- The development warning stays and becomes accurate, because the default theme
  is now really used.

**`colorFromVariant`**

- Resolves the variant against `themeConfig.colors`. That map is already the
  merge of `RottProvider config` colors and `rott.config` colors, with
  `rott.config` winning on collisions, so the documented precedence holds and
  provider-only colors start resolving.

**Prototype extensions**

- `arrayExtensions.ts` and `stringExtensions.ts` define their members through
  `Object.defineProperty` with `enumerable: false` (and `writable` and
  `configurable` set to `true`). The methods and their behavior are unchanged;
  `for...in` stops listing them.

**Button**

- `fontFamily={fontFamily ?? (fontWeight ? undefined : 'Markpro-Bold')}` — an
  explicit `fontFamily` wins; without one the current behavior is unchanged.
- `TouchableOpacity` receives `disabled={props.disabled || isLoading}` after the
  props spread, so a loading button ignores presses. The styles still read only
  `props.disabled`, so a loading button looks exactly as it does today.

**Image**

- Only a plain `{uri}` object source is extended with `cache: 'reload'`, which
  is today's behavior for remote images. Number (`require()`) and array sources
  pass through untouched.

**List**

- The skeleton array length is `estimatedItemSize === undefined ? 1 :
  Math.max(0, Math.round(estimatedItemSize))`. This keeps the current count and
  removes the crash.

**TabWidget**

- Replace the inline `SceneMap` with a memoised
  `renderScene = ({route}) => tabs?.[Number(route.key)] ?? null`. The elements
  keep their type across renders, so scenes are no longer remounted.

**Header**

- The back press calls `goBackFunction` when it is provided and
  `themeConfig.goBack` otherwise. `preventGoBack` still suppresses both, and
  `leftIcon.onPress` still runs first.

### Docs

Every behavior change gets its English page updated and the Turkish mirror under
`docs/i18n/tr` kept in step:

- Notification: the new provider prop, the non-blocking default, the `onPress`
  argument and a working `hideAll`.
- Button: `fontFamily`, and `isLoading` blocking presses.
- Amount input: the accepted `value` shapes and the currency icon.
- Image: local sources.
- Email input: controlled and uncontrolled use.
- Header: `goBackFunction`.
- Container: `showStatusBar` defaults to hidden.
- rott.config and installation pages: a missing config keeps the defaults.
- Release notes: a 0.9.1 entry that lists the behavior changes.

## Testing

- Every item gets a regression test that fails on `development` and passes after
  the fix. The throwaway tests from the review are the starting point.
- The repository's Jest setup cannot render `react-native-tab-view` or a real
  toast: the root devDependencies pin `react@19.2.4`, while React Native 0.81's
  legacy renderer, which Jest loads, requires exactly `19.1.0`. Tests for
  `TabWidget` and `NotificationProvider` therefore stub those two libraries in
  their own test files and exercise this library's logic.
- Tests that need the real theme (`rott.config` resolution, provider colors)
  call `jest.unmock` for `src/theme` and `src/providers` in their own files,
  following the existing `src/theme/__tests__/theme.test.ts` pattern.
- The gate before asking to push: `yarn test`, `yarn lint`,
  `yarn format:check`, `yarn typecheck`, `yarn prepare` and the docs build.

## Release

- Bump `package.json` to 0.9.1 and add the release notes entry.
- Rename the `publish` script. npm runs the package's `publish` script after
  every `npm publish`, including `--dry-run`, so the current
  `"publish": "npm publish --access public"` starts a nested publish. The new
  name is `release:npm`, and `publish:patch`, `publish:minor` and
  `publish:major` call it.
- Pushing, opening the PR, tagging and publishing wait for explicit approval.

## Related work, not in this release

- The rest of the 2026-06-22 design is unimplemented: `RottProvider` still
  merges into the previous `themeConfig` (top-level keys accumulate), top-level
  provider fields such as `goBack` override `rott.config`, and the provider picks
  its language from `config` before `rott.config`.
- `AmountInput` spreads its remaining props onto the wrapper `Item`, so
  `onBlur`, `onFocus` and `testID` never reach the text inputs.
- `DateInput` calls `onDateChange` on mount, ships a Turkish default placeholder,
  and freezes its modal config on first render.
- `List` derives the skeleton row count from a pixel size.
- `Image` forces `cache: 'reload'` on every remote image.
- `react-native-toast-notifications` has not been updated since 2023 and causes
  the `SafeAreaView` deprecation warning.
- Accessibility roles and states are almost entirely missing.
- The docs use icon names that do not exist; the docs correctness net covers
  this.

## Risks

- Language and theme stay module-level state. Two `RottProvider`s with different
  languages would share whichever rendered last — the same limitation
  `themeConfig` already has.
- `formatMessage` no longer subscribes its callers to language changes. It used
  `useContext`, so a runtime language change re-rendered every caller; it now
  reads the active language when it is called. A component that does not
  re-render for another reason keeps its old text until its next render.
  Components that must follow a runtime change use `useTranslator`.
- Removing the `useContext` mock can surface failures in unrelated tests. They
  get fixed in the same task, not re-mocked.
- The notification default changes from blocking to non-blocking. Apps that
  relied on it must opt in; the release notes say how.
- `TabWidget` and toast integration are verified against stubs. A manual check
  in `examples/consumer-app` is recommended before publishing.
